Decisions worth keeping:

- **Custody chain serialised with a Postgres advisory lock.** Without it two concurrent appends
  both read the same tail row and write siblings claiming the same `prevHash`, forking the chain.
- **`AuditLog.timestamp` is `@db.Timestamp(3)` on purpose.** The row hash covers the ISO-8601
  timestamp and JS `Date` carries only milliseconds; at Postgres's default microsecond precision a
  value would not round-trip identically and every verification would fail on read-back. Do not
  widen that column.
- **Worker claim uses `FOR UPDATE SKIP LOCKED`.** Three CUDA machines run the same worker from
  week 3; without an atomic claim two of them train the same scene.
- **Job transitions validated in one place** (`src/lib/job-state.ts`) against the contract's state
  machine, with terminal states enforced, and `FAILED` requiring readable error text.
- **Workers authenticate with a separate `WORKER_TOKEN`**, not user JWTs, so a leaked machine token
  cannot be replayed against investigator routes. Added to `.env.example`.
- **Cross-owner scene reads return 404, not 403**, because a 403 confirms the id exists.
- **`storage.ts` is the only module that joins paths** and rejects keys escaping `ASSET_DIR`;
  `urlFor()` is the object-storage seam.
