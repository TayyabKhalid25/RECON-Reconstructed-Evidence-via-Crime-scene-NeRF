## FTW-25, the marker

- No marker artwork existed and nothing on the box could generate one (no PIL, no OpenCV, no
  ImageMagick), so `tools/make_marker.py` writes the sheet directly as PDF and SVG from stdlib.
- Chose a feature-dense asymmetric pattern over an ArUco/AprilTag fiducial. The handbook commits
  to AR Foundation's tracked image manager, and ARCore scores candidate images on feature
  richness — bare binary tags score badly. COLMAP wants the same density to find the marker in
  the reconstruction. Two orientation glyphs (L top-left, lone block bottom-right) make a
  90/180 degree frame error visible instead of silently plausible.
- Sheet carries a 100 mm scale bar, because a print dialog claiming 100 percent and the paper
  actually being 100 percent are different facts.
- Printed A4 at 100 percent, measured **170.0 x 170.0 mm** on the black ring's outer edge.
  Recorded in `docs/FRAMES.md` with the `physicalSize = 0.170 m` value Unity needs.
- Generator is seeded (20260822) and committed, because the marker is not interchangeable: a
  freshly generated reprint is a different image and would not match a reference image library
  built from this sheet. Generated PDFs/SVGs are gitignored, CI blocks binaries.

## Product discussion: server-side rendering instead of on-device splats

Asked whether moving rendering to the server and streaming to the phone would be cheaper or
more efficient. Conclusion: it breaks the AR mode outright rather than trading off. Motion to
photon needs roughly sub-20 ms; pose uplink plus render plus NVENC plus network plus decode is
50-80 ms even on good Wi-Fi, which at a normal 30 deg/s head turn is about 2 degrees of
registration lag. Worse, the anchor-accuracy test measures doorway alignment in centimetres, so
streaming would have it measuring network jitter instead of reconstruction quality.

Where it does win is the non-AR web dashboard viewer, which the handbook already proposes at
line 496. Costs: on-device is one download per scene per device; server-side pins a GPU per
viewer, roughly 500-800 USD/month for an always-on cloud box, or contention with training on the
Legion's single 8 GB card. One genuine advantage: evidence never leaving the server is a
stronger chain-of-custody story, worth a line in the report either way.

**Decision: not now.** FTW-16 (splat FPS on a real phone) is the measurement that decides this
and it has not been taken; the handbook is explicit that everything else is pointless until it
is known. Proposal is due 4 Sep and defence 18 Sep with on-device pinned, and re-architecting
would rewrite Track C's definition. Server-side rendering goes in the proposal as future work,
which reads as latency-budget awareness rather than an omission.
