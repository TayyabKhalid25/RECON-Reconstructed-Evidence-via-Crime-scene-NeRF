# Session: 2026-09-30 (Tayyab)
**Machine:** Tayyab's Machine (S20 FE for testing)
**Goal:** Phase 1 mobile performance benchmark on an untethered physical device for FTW-30.

## Progress
- Picked up **FTW-30** to test the raw rendering performance of 178k and 164k splats on mobile via `arloopa/UnitySplats`.
- Created `MobilePerformanceHUD.cs` to render an on-screen overlay tracking FPS, 1% Lows, Battery %, System RAM, and VRAM directly in the physical AR view.
- Attempted to implement thermal tracking via `SystemInfo.batteryTemperature` and `Application.thermalStatus`, but encountered compiler errors (`CS0117`) as they are unsupported natively in this Unity build. Removed them in favor of manual ADB polling (`adb shell dumpsys battery`).
- Evaluated the `com.unity.adaptiveperformance` package as an alternative for thermal metrics, but chose not to install it to keep the benchmark pure and avoid unneeded heavy dependencies for Phase 1.
- Created `SplatControllerHUD.cs` to allow on-device manipulation of the splats without needing to physically move the phone:
  - Built a camera-relative D-Pad for translation (`^`, `v`, `<`, `>`).
  - Implemented Pitch/Yaw rotation controls and Scale controls.
  - Added a Splat Selector array to seamlessly toggle between multiple splats (e.g. 178k vs 164k) in a single session without resetting the camera position.
- Redesigned `SplatControllerHUD.cs` midway to split Move and Rotate controls into separate UI "pages" to prevent overlapping buttons on portrait mobile screens.
- **Benchmark Run:** Compiled a Release build (Development Build unchecked) and ran a 5-minute untethered test on the S20 FE.
  - **Result:** 14 FPS (12 FPS 1% Low) for *both* the 164k and 178k splats. 
  - ~60%/hr battery drain. Minor heating. Memory (RAM/VRAM) displayed hardware limits.
- **Diagnosis:** Scaling the splat down to a small corner of the screen instantly restored performance to the 30 FPS AR Foundation cap. This definitively proved the 14 FPS limit is caused by **fill-rate bottlenecking (alpha overdraw)**, not vertex processing limits. The GPU is choking on blending overlapping pixels, which is why the 8% geometry difference between 164k and 178k didn't matter.
- Discovered CDRIN SIGGRAPH 2025 research ("Optimizing Gaussian Splat Rendering for Mobile and Standalone VR") which proves a 3.3x performance boost is possible on this exact rendering architecture via aggressive alpha clipping, stencil buffer capping, quad rescaling, and Nth-frame sorting.
- Updated `docs/RESULTS.md` with the 14 FPS baseline and an explanation of the fill-rate bottleneck to ensure Wahaj does not panic about the splat budget yet.
- Checked off the first two Track C milestones in `docs/Forensic-NeRF-FYP-Handbook.md`.
